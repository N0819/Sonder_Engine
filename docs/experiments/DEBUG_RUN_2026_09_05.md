## Method: the scratch database

`tools/export_bench.py prepare --src engine.db --chats 114 115 --out
<jobs>/dbg2/bench.db --model default=3:google/gemini-3.8-flash`, 4.5 s, 23 MB.
Each chat is exported through `persist/chat_archive.py` over a `?mode=ro`
connection to the source (`read_only_session`; a write raises), the scratch
is created fresh with `db.init()`, the archives are imported through the
service the UI's import button uses, and `providers` whole plus every
`settings` row but the host account are copied table-to-table inside SQLite
(the owner's ruling of the day: everything main has for model wiring, not a
subset). `SETTINGS_FORCED` turned adult content, backdrops and ambience off
and capture ON with full bodies, so `read_trace` (over
`pipeline_trace.export_turn_debug`) could say what each stage was SENT; the
first eleven turns (chats 114/115) ran before the ruling and have no capture
rows -- the fresh scenarios have them, one `trace_<turn>.json` per beat in
the job scratch dir. `scan` was run over everything written outside the
scratch db before this document was committed: no provider key in any file.
Writers' Room calls are not captured (only `agents/runtime.py` records) --
a gap, noted. The harness is documented in `docs/guides/TESTING.md` and
proven by `tests/test_export_bench.py`.

Scenario authoring: `web.app.chat_new`, `persona_create`, `chat_edit`,
`char_create` (which returned `character_card_warnings`: none for any of the
four cast), `chat_add_char(already_known=True, already_known_cast=True)`.
Fields the World Browser has no route for -- `light_shape`, `light_height`,
`steadiness`, `sound_source`, `state.running` -- were written into the scene
blob by hand as a host would (recorded per phase as `host_sources`); every
other geometry fact went through the routes.
