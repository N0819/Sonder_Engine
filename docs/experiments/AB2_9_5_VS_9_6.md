# Second A/B: ten turns on alpha 9.6 against ten on alpha 9.5

Run 2026-08-19, on the eve of the alpha 9.6 release. The first A/B
([`AB_9_5_VS_9_6.md`](AB_9_5_VS_9_6.md)) ran mid-repair, on an engine whose
slowest path turned out to be an unconfigured model role, and with different
models on the two sides. This one fixes both of those and adds five turns that
exercise floors 9.5 never claimed.

A green suite never runs a model. It can tell you nothing changed shape; it
cannot tell you a character stopped reasoning well. That is what this is for.

## The setup, and what is different from the first run

| | first A/B | this one |
|---|---|---|
| models | different per side (contention avoidance) | **identical**: `x-ai/grok-4.3` on every role, both sides |
| roles configured | 6 of 18; twelve fell back to `default` | **all 18 explicit**, so no role falls back |
| execution | both installs in parallel | **sequential**, so timings are not contended |
| turns | 10 / 10 | 10 shared + **5 more on 9.6 only** |

Both installs ran on their own database, seeded read-only from the owner's
provider config with provider IDs preserved. `engine.db` was never opened for
writing.

The five extra turns run on 9.6 alone and are reported separately. Running them
on 9.5 would compare an engine against features it never claimed; the shared
ten are the comparison, and every end-state number below is bounded to them.

**Prose is not compared.** Two runs of one model produce different sentences
from identical input. What is compared is what the engine DID.

## The result

**Both installs completed every turn. Zero commit errors, zero rollbacks, no
missing stages, no tracebacks.** Identical plan shape: 5 steps on turn 0, 9 on
every turn after — with one exception, and it belongs to 9.5 (turn 6 ran 10,
an extra contested-reaction step).

|---|---|---|
| turns committed | 10 | 10 |
| commit errors / rollbacks | 0 | 0 |
| turns missing narrator or commit | none | none |
| steps recorded | 87 | 86 |
| stored variants (rerolls) | 87 (1 per step) | 86 (1 per step) |
| commit warnings | 3 | 1 |

## The firewall, which is the thing worth checking

Turn 4 says, to one character in front of another:

> "The packet is for the Warden. Do not tell Halden that."

| | Sable (addressed) | Halden (present, not addressed) |
|---|---|---|
| 9.5 | 1 memory naming the Warden | **0** |
| 9.6 | 1 memory naming the Warden | **0** |

**Both engines held.** The secret reached its addressee and no one else.

But the two recorded it differently, and the difference is 9.6's:

- 9.5: `I heard **Wren** say: "The packet is for the Warden…"`
- 9.6: `I heard **the lean courier** say: "The packet is for the Warden…"`

Nobody ever introduced the player. Sable has not earned the name, so 9.6 stores
a description and 9.5 stores the name — the identity floor doing exactly what
`Design.md` § "A character calls the player what they may legitimately call
them" says it should, and 9.5 leaking it.

## Two defects this run found, both now fixed

Neither was found by 8,118 passing tests. Both are in the release.

1. **Every unrecognised body was labelled with a dangling preposition.** 9.6
   rendered `the lean courier in`, `the broad man in`, `the old porter in`.
   Two tail-trims in `_unknown_actor_label`, each correct, neither re-reading
   what the other uncovered: the cap leaves "lean courier in a rain-darkened",
   the trailing-word trim sees a content word and passes, the amputated-phrase
   rule cuts the fragment, and nothing runs the trailing trim again. It needs a
   summary long enough to be capped AND a preposition inside the first five
   words, which is why five earlier repairs to that function never produced it.
   It matters because this label goes into perception views, into prose, and
   into the MEMORIES written from them, where it is durable.

2. **A named character was put under on somebody else's collapse.** Turn 13
   said the hooded figure went down; the committed ledger carried
   `subject_id: "Halden"`, `level: unconscious`, `cause: "collapse against
   gate"` — for the lift operator standing beside them. The narrator's prose
   was right; the ledger was not, and the ledger is what gates. Halden then
   runs no character step and reads as a character who has gone quiet, which
   is the exact failure the awareness work exists to prevent. The onset floor
   guards only the PLAYER, and its support check is by its own docstring "not
   subject-attributed" — so a beat that genuinely contains a collapse licenses
   gating anybody in it. Fix and argument: see the commit and
   `AGENTS.md` § "Going under and waking up".

## What the five 9.6-only turns exercised

| turn | intent | result |
|---|---|---|
| 10 | a wrist held fast | `contact_ops` grip, hand→wrist, `motion: settled` |
| 11 | letting go | `contact_ops` remove, matched to the same pair |
| 12 | smelling a sealed packet | **nothing but `time`** — see below |
| 13 | a body going unconscious | `conditions`, canonical `kind: awareness` |
| 14 | shaking it awake | `conditions` on the same `condition_id` |

Two honest negatives:

- **The scent beat produced no scent.** The authoring surface exists and the
  channels are ledgered, but a player holding a sealed packet to their face and
  asking whether someone across the room can smell it produced only a clock
  tick. Nothing was emitted to refuse; the Director simply did not use the
  channel. Registered rather than fixed here — this is a prompt question, and
  one scenario is not enough evidence to shape a rule from.
- **The wrist-hold was recorded as a contact, not a restraint.** Defensible —
  the body specialist is explicitly told not to file an embrace or a grip as
  restraint — but it means this run did not exercise the restraint records or
  their exits, and the restraint half of that work remains proven only by
  tests.

## The provider finding, which is not about the engine at all

The first attempt at this run used the owner's live model config
(`deepseek/deepseek-v4-flash-0731` on OpenRouter for director, narrator and
default) and had to be abandoned. Turn times: 63s, 152s, and then **910s**,
where the client gave up. Re-run on `x-ai/grok-4.3`, same engine, same
scenario, same machine: **13.6s, 20.6s, 30.0s.**

A trivial one-token probe answered in 1.9s on the same model and endpoint, so
it is large-context requests specifically that stall. Worth knowing before
blaming a turn on the engine.

And the abandoned run produced a second useful result: after the client timed
out, every later submission returned

> HTTP 409 — This frame still has an active pipeline. Abort it and wait for the
> aborted response before submitting another turn.

That is `_require_frame_idle` doing its job. The abandoned turn committed
correctly fifteen minutes later. The harness was wrong; the engine was not. The
driver now raises its ceiling and issues the abort the engine asks for.
