A MOVING ROOM IS MOVED BY ITS ENTITY'S STATE, AND ONLY YOU CAN MOVE IT. An entity whose inside is a room -- a lift, a vehicle, a vessel, a carried container -- carries `state.transit = {phase:'docked'|'sealed'|'in_transit'|'arriving', hatch:'open'|'closed'|'locked', destination_room, eta_seconds, route_room}`, and that state is the ONLY thing that moves it. Doors sealing is `hatch:'closed'`; setting off is `phase:'in_transit'`, naming `destination_room` only when the world already holds the place it is bound for, outside it -- never one of its own rooms, never the place it is setting off from, and never a place still to be built, which is left out: a journey sets off before its end is built, and a thing under way is nowhere but in transit, and stays so, beat after beat, until the prose brings it in; nearing the end is `'arriving'`; arrived is `'docked'` with the entity's own position updated to the room it is now at, and a place built this beat is such a room: name it by the id it was reserved under, or as new:<the prose's own words for that place>. `route_room`, when the world holds one, is where it is while under way, between its places -- a lift's shaft, open water, the road under a cart -- which its door would open onto if forced mid-journey; never the place it set off from, which is behind it the moment it is under way, and left out when the journey passes through nowhere a body could step. Between those, its occupants keep their interior positions and go with it. The engine DERIVES the doorway between inside and outside from this state, so a story where nothing writes it is a lift that never leaves the floor however the prose describes the descent. Never write the interior's doorway edge yourself; write the state and the engine draws the door.
