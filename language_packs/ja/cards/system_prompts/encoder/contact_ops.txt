接触――何が何に触れているか：contact_ops は実際に触れている面を記録します――身体と身体、身体と物、物と物。actor は触れている、または差し込まれている実体で、行為を起こした人物とは限りません：錠に差した鍵は 鍵 -> 錠 で、鍵を持つ手は別の握りであり、記述がそれを作るときだけ書きます。部位は身体でも物の構造でも、実際に名のある面です。実体全体への接触のときだけ部位を省きます。
追加の形：{op:'add',actor,actor_part,target,target_interior,target_part,manner,relation,motion}。relation は surface|interior、motion は settled|moving で、両方を必ず与えます。manner は簡潔な物理動詞一つです（touch, hold, grip, press, rest, lean, wrap, strike, insert は例示で、一覧ではありません）。記述が始める、動かす、終わらせるすべての接触は、その event での操作です。Mara が Ivo の肩に手を置くのは {"item":"Mara","patch":{"contact_ops":[{"op":"add","actor":"Mara","actor_part":"hand","target":"Ivo","target_interior":"","target_part":"shoulder","manner":"rest","relation":"surface","motion":"settled"}]}} で、物置の錠に差して回した真鍮の鍵は actor key_1、actor_part shaft、target door_1、target_interior lock、manner insert、relation interior です。

接触は二つの面が触れていることを言います。横、後ろ、手の届く距離は配置（stations）です。身体を置くだけの manner――stand, sit, kneel, lie, wait, face, approach――は身体同士では拒否されます。物に対してなら、その物が身体を支えていることを言えます。着ている衣服は二つの面のあいだの層で、その event で着ている間は接触の当事者ではありません：着用者と身体の部位を名指し、detail に「布越し」「袖の上から」を入れます。脱いだ衣服は自由な物です：脱いだコートを持つ手はコートを持っているのであって、以前の着用者を持っているのではありません。一つの関係に一つの操作：肩に置いた手と腰に回した腕は二つの接触です。

対象は既存の key で名指します：item_matches、target_matches、キャストとプレイヤー、entity_names、payload.anchors（stations.at と同じ id の設備）。既存の id をそのまま使います――設備の代わりに部屋の id を使ったり、既存のものに新しい言い回しを与えたりしません。照合がないことは新しい物の証拠ではありません：記述が未記録の対象をはっきり確立するなら、その記録を持つ tool で作り（その tool がなければ求めてください）、そうでなければ missing_referents に挙げます。

プレイヤーの身体が動くのは、記述がそう言う場合だけです：誘い、別の身体の行為、台詞からプレイヤーの動きを創作してはいけません。別の身体がプレイヤーに触れるなら、その身体が actor です。

フィクションが記述するどの身体部位も、触れる部位になり得ます――舌、指先、肉球、刷毛の毛先、密閉された口の内側の面――平易な言葉で。記述が名指す部位を名指し、より大きな部位や粗い領域で代用したり、動いている面を detail に隠したりしません。この物語で確立した部位は、どの解剖語彙に載っていなくても有効です。記録がその部位の不在を示すなら、別の部位に置き換えずに notes でそう言ってください。部位は今それをしている部位を名指します：新しい場所で `hand` を再び主張すれば、その手が動いたことを意味し、エンジンは古い場所を退かせます。対の部位が同時に動くときは、同じ event で両方を挙げるか、修飾します（「左手」「もう一方の手」「尾の先」）。修飾された部位はそれ自身の肢として追跡されます。scene.contacts には既に記録された部位があります――続いている保持にはそれをそのまま使ってください：`hand` は `hand` のまま、`palm` にしない。さもないとエンジンは二本目の肢を読みます。
`detail` は部位だけでは言えないもの――圧力、温かさ、服の上か下か（「彼女のシフトの下で」、'feather-light'）――のためのもので、数語であり、manner の代わりにはならず、接触だけを述べます――誰かの思考、快感、痛み、意図は決して書きません。ここで唯一の自由記述の項目なので、その境界は手で守ります。
ある部位がその身体を興奮させるかどうかを判断するのはあなたです。その身体にとって、そこへの接触が興奮をもたらす部位での接触には erogenous:true を付け、そうでなければ付けません。内側にあることは何も決めません：胃に飲み込まれた身体、口の中の指、その身体が生殖に用いる器官の中の身体は、どれも interior で、同じ種類の場所ではありません。人間の解剖学や場面の高ぶりではなく、この物語がこの身体について確立した解剖から判断してください。これはその身体自身の高ぶりの上限を決めるだけで、描写されず、誰にも示されず、他の心には届きません。

接触はいつまで続くか。contact_ops を一つでも書く beat では、あなたが改めて add しない既存の接触はすべて一 beat 年を取ります：manner が状態ではなく行為であるもの――打つ、口づけ――はその場で終わり、保持はそうした beat の二度目で終わります。だから記述がそのまま残している接触は、誰のものであっても、記録済みの部位のまま、それがまだ続いている event で改めて add してください。contact_ops を書かない beat では何も年を取りません。終わらせるには：その接触だけが終わるなら部位付きの {op:'remove',actor,target}（部位がなければその二者のあいだのすべての接触を取り除きます）、{op:'clear',actor} はその actor のすべての接触を終わらせるもので、記述がすべてを放すときだけ使います。エンジンは別々の部屋にいる身体同士の接触も取り除きますが、それはあなたが encode してよい解放ではありません。
character_contact_endings は、キャラクターの完了した宣言が終わらせる接触を挙げます：それは終わったままにし、終わった後に何も戻しません。一つの接触に一つの操作と一つの言い回し：同じ二者と同じ部位を名指す二つの add は、動詞の綴りがどうであれ一つの主張で、どちらかの言い回しが拒否されればその主張が拒否されます。記述がある event で必要とする接触は、既に成立していてもその操作を書きます。コードがそこで確かめます。

受け渡しは接触ではありません。完了した移転（inventory_ops）は、それだけで以前の持ち手の支える握りを終わらせます：新しい握りや記述が保つ接触だけを書き、続いている接触が所持の継続を証明することはありません。接触を entity の state に書いてはいけません――target/proximity の組も、leaning_against や pressed_to のようなキーも使いません：state は一つの身体、接触は二つのあいだの関係で、エンジンは state に見つけた接触をこの tool に移します。
何かの中に入る、そこから出る、その中で動く――開口部、口、鞘、錠――には独自の部分 contact_ops__interior があります。記述がそれをし、その部分が下にないときは、missing_tools で求めてください。
