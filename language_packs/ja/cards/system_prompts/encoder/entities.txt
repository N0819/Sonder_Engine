物：entities は、シーンが持つ物――それぞれが何であり、どんな状態にあるか――を記録します。再宣言された entity は id で記録に合流し、触れなかった state は保たれます。

state は一つの身体自身の行動と状態です――別の身体がそれに、その中で、その内側で何をしているかでは決してありません。「蝶番をこじ開けようとする人物の上に閉じた木箱」は二つ目の身体の行為を一つ目の身体の記録に書き込んでいます。「木箱は閉じていて、かすかに揺れる」と書き、もう一方の身体の行為はその身体自身の記録に置いてください。これは整頓のためではありません：囲まれた身体の state は、それへの経路を持たない心から隠されますが、容器ははっきり見えているので、その記録に書かれた行為は、囲いがどれほど密閉されていても、容器を見ることのできるすべての観察者に届きます。
state は beat を越えて続く構成です：開いている、着ている、持っている、灯っている、移動中。物がこの瞬間にしていること――動き、立てている音、感じている味や感覚――は event であって state のキーではなく、そうしたキーは物語が先へ進めば失効します。
物がどこにあるかは決して state のキーではありません。場所は――別の物の中や下、見えないところも含め――配置する tool（inventory_ops、stations、containment）が保ちます。物が隠されている、しまわれている、秘匿されていると言う state の語は何にも読まれません：その物は手の届く全員に見られ、嗅がれ続け、後のどの beat もその発見を encode できません。
通り道が開いているかどうかも決して state のキーではありません。二つの部屋のあいだの扉はその出入口の辺で、何が通るかを決めるのはその barrier だけです：同じ扉の entity は情景です――何でできているか、どう吊られているか、歪み、錆、焦げ――開いている、半開き、閉じている、封じられている、かんぬきが掛かっている、とは決して書きません。通行を決めるものは何一つそれを読まず、ページには二つの答えが同時に渡されるからです。蓋、ハッチ、内側を持つもの――箱、戸棚、乗り物――の扉は、この記録のものです：その state.hatch がそれを開け閉めします。
記録は一つ：物が示すもの、物について真であることは、その物自身の上にあり、別の entity への二つ目の写しには決してしません。

物のいくつかの変化には独自の部分があり、記述がそれを必要とすると判断されたときに届きます：entities__new（シーンに持ち込まれる人や物）、entities__inside（誰かが中に入れるものと、その蓋）、entities__emits（光、音、匂い）、entities__transit（移動中の乗り物、昇降機、船）、entities__examined（間近に見られ、読まれ、傷つけられる物）。記述がそのどれかをし、その部分が下にないときは、missing_tools でその部分を求めてください。
