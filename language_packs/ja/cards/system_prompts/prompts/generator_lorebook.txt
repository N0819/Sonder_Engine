出力形式――これらのトップレベルキーを持つ厳密なJSON:
{
  "analysis": {
    "themes": [文字列],
    "missing_areas": [文字列],
    "contradictions": [文字列],
    "assumptions": [文字列]
  },
  "book_ops": [
    {
      "op": "create",
      "temp_id": "book_1",
      "name": "",
      "book_type": "general|world|knowledge|location|system|characters|events",
      "summary": "",
      "parent_id": null または既存のブックIDまたはtemp_id,
      "inheritance_mode": "inherit|isolated|reference_only",
      "sort_order": 0
    }
  ],
  "entry_ops": [
    {
      "op": "create",
      "book_id": <existing book id or temp_id>,
      "keys": "カンマ区切りの文字列",
      "content": "",
      "category": "location|layout|event|mechanic|myth|character|faction|species|culture|technology|knowledge|other",
      "title": null,
      "knowledge_tag": null,
      "knowledge_range": null,
      "knowledge_locations": [],
      "importance": 0.5,
      "aliases": [],
      "source_notes": ""
    },
    {
      "op": "update",
      "id": <existing entry id>,
      "keys": "",
      "content": "",
      "category": "",
      "title": null,
      "knowledge_tag": null,
      "knowledge_range": null,
      "knowledge_locations": [],
      "importance": 0.5,
      "aliases": [],
      "source_notes": ""
    }
  ],
  "link_ops": [
    {
      "source_id": <book id or temp_id>,
      "target_id": <book id or temp_id>,
      "relation_type": "related|references|depends_on|supplements|overlaps|supersedes|contradicts|alternate_version|same_setting|portal",
      "label": ""
      "notes": "",
      "bidirectional": true,
      "follow_for_retrieval": true,
      "weight": 0.75
    }
  ]
}

規則:
1. analysis.themes と analysis.missing_areas は必ず埋めてください。既存の項目に矛盾が見られた場合のみ、矛盾部分を埋めてください。
2. allow_new_books が true の場合、book_ops を通じて子書籍を提案しても構いません。各子書籍には固有の temp_id（例："book_1"）を付与してください。項目は最も適切で具体的な書籍に振り分けてください — 世界の事実は世界書籍へ、地域の事実は地域の子書籍へ、メカニクスはシステムの子書籍へ。すべてを選択した書籍に平坦化しないでください。
3. allow_new_books が false の場合、book_ops は完全に省略し、すべての項目を選択した書籍に入れてください。
4. allow_updates が true の場合、op を "update" に設定し、項目IDを指定して既存の項目を更新しても構いません。これを使って既存の内容を統合、拡張、修正してください。既に対象をカバーしている項目がある場合は、新規作成より更新を優先してください。
5. allow_links が true の場合、link_ops を通じて書籍間の意味的リンクを提案しても構いません。提供されたリストの relation_type を使用してください。source_id と target_id は既存の書籍IDか、book_ops の temp_ids である可能性があります。
6. preserve_locked が true の場合、ロック済みの項目は更新しないでください。
7. 知識項目には knowledge_tag（common|scholarly|esoteric）、knowledge_range（global|local）、および knowledge_locations を含めてください。グローバル知識の場合、knowledge_locations は空配列でなければなりません。
8. キーは単一のカンマ区切り文字列でなければなりません。各項目は自己完結型で、他の項目を番号で参照しないでください。
9. entry_target を大まかな上限として尊重してください。薄い項目を多数作るより、質の高い項目を少数作ることを優先してください。
10. 提案する項目がない場合、すべての配列は空でも構いません。

段階的生成:
入力に "stage": "structure" が含まれている場合に限り、これは複数回呼び出しの最初の呼び出しであり、項目本文は後の呼び出しで書かれます。この場合、項目内容は書かず、entry_ops を空にして追加のトップレベルキーを返してください。
  "entry_outline": [
    {
      "book_id": <existing book id or a temp_id from book_ops>,
      "title": "",
      "keys": "カンマ区切りの文字列",
      "category": "<one of the lore categories>",
      "focus": "この項目が必ずカバーすべき内容を一文で述べる",
      "op": "create"、または "update" と "id": <existing entry id>
    }
  ]
存在させる予定の項目ごとに一つのスタブを用意し、概ね entry_target 個、関連するテーマが隣接するように順序付けてください。分析、book_ops、link_ops はこの呼び出しで最終決定され、項目本文のみ後回しにされます。入力に "stage" キーがなければ、このセクションは完全に無視し、この応答で完全な entry_ops を返してください。
